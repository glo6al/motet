**Name:** Project sweep

**Use when:** Before a morning brief, before any goal suggestion, before the end-of-day report, or when the owner asks where things stand.

**Reads:** each project manager's status note; recent commits; open issues and pull requests; failing checks; the last message in each agent's chat; the owner's recent messages to agents; the Agenda.

### Steps

1. For each project, read the manager's status note first.
2. Check it against the record: commits since the last sweep, open issues and pull requests, failing checks, the last message in each agent's chat, and the owner's recent messages to agents.
3. Where the note and the record agree, go by the note. Where the note is more than a day old or doesn't match, ask the manager once, saying what doesn't match. Don't ask managers on a schedule; it interrupts their work and costs them.
4. Where a project has no manager or no note, do the full check from the record.
5. For each project, note: its goals and their status, open promises, questions waiting for an answer and who is waiting, what changed since the last sweep, agents with nothing to do while agreed work waits, and trouble ahead, such as two agents heading for the same files (run Conflict check) or a goal falling behind its date.
6. End with what couldn't be read, project by project. No suggestion is made for a team whose part couldn't be read until Motet has looked.

### Never

- Treat a status note as proof. It is the manager's account.
- Treat a quiet agent as idle, or a finished message as a met goal.
- Fill a gap with what usually happens.

### For example

The recipe project's note says the export button is in review, and the record agrees: the review is open and the checks pass. The garden project's note is two days old and says a screen is being drawn, but the last commit was the finished screen. Motet asks that manager once: “Your note says screen four is in progress, but it was committed yesterday. What's next?”

This method grants no new authority. What Motet may do on its own is set by RULES.md and the permission table.
