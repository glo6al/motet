**Name:** Close out a goal

**Use when:** The work for a goal has merged or shipped, or the owner says a goal is done.

**Reads:** the done line recorded at kick-off, the record of what merged or shipped, and the project's status note.

### Steps

1. Check each part of the done line against the record. If a part isn't met, the goal is not done: say which part, and go back to Next step after a turn.
2. Make sure the manager's status note says the goal is done. If it doesn't, ask the manager to update it.
3. Record in memory what was done, when, and anything learned along the way. Close the promises tied to the goal.
4. If the team has another goal, start it with Kick off a goal. If the team is now between project goals, ask its manager to suggest a few for the owner to choose from.
5. Report it in the end-of-day report, not in a separate message, unless the owner asked to hear at once.

### Never

- Mark a goal done when part of its done line isn't met.
- Set the team's next project goal. The manager suggests and the owner chooses.

### For example

The export button merged at noon. Every part of the done line is met, and the manager's note says so. The team has no next project goal, so Motet asks the manager for suggestions, which go in tomorrow's morning brief.

This method grants no new authority. What Motet may do on its own is set by RULES.md and the permission table.
