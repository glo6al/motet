**Name:** Kick off a goal

**Use when:** The owner has set a goal, or a day's goal starts at the set time because the owner hasn't answered.

**Reads:** the goal as the owner set it, the project's status note, who is on the team and who is free.

### Steps

1. Write the goal down in one sentence, with what “done” looks like: what will be true, how it will be checked (tests, the other provider's review, the designer's visual pass), and anything the owner put out of bounds. For a day's goal that started at the set time, use the done line from the morning brief. If the owner's words don't say what done looks like and the brief didn't either, ask before handing it on.
2. Hand it to the project's manager with that sentence. Where the project has no manager, hand it to the builder whose area it is.
3. If no one on the team is free and the owner agreed the work, start a new chat for it, with the project's rules and the goal. Tell the owner, and why.
4. Confirm someone has actually started: a reply that names the first step, a branch, a commit or a plan. A delivered message is not a start. If nothing has started by the next check, follow Unstick an agent.
5. Record in memory the goal, who has it, when it was handed over, and the done line, so Close out a goal can check against it later.

### Never

- Set, widen or change a goal. Only the owner does that.
- Start work the owner didn't agree, or hand a goal to an agent outside the project's team without saying so.

### For example

The owner sets “Let users export their saved recipes”. Motet hands it to the manager as: “Users can download their recipes as a file from the settings screen; done when the tests pass, the other provider's review is clean and the designer has checked the screen. Payments are out of bounds.” Twenty minutes later the builder has a branch and a plan, so it has started.

This method grants no new authority. What Motet may do on its own is set by RULES.md and the permission table.
